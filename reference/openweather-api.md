# Справка по OpenWeather API

## 1. Geocoding API — город → координаты

```http
GET https://api.openweathermap.org/geo/1.0/direct
```

| Параметр | Обяз. | Значение в проекте | Смысл |
|---|---|---|---|
| `q` | да | название города | «Москва», `Saint Petersburg` |
| `limit` | нет | `1` | сколько совпадений вернуть |
| `appid` | да | ключ из `.env` | авторизация |
| `lang` | нет | `ru` | язык названий, если API его локализует |

Ответ — **массив**:

```json
[
  {
    "name": "Москва",
    "local_names": {"ru": "Москва", "en": "Moscow"},
    "lat": 55.752,
    "lon": 37.6156,
    "country": "RU",
    "state": "Москва"
  }
]
```

Город не найден — `200` и **пустой массив** `[]`, а не ошибка. Поэтому одной
проверки статуса мало: нужно смотреть на длину списка.

Совпадения отсортированы по популярности, первый элемент — «главный» город
с таким названием. Поэтому `data[0]` даёт ожидаемый результат для «Приморска»,
«Санкт-Петербурга» и т.п.

## 2. Current Weather — текущая погода

```http
GET https://api.openweathermap.org/data/2.5/weather
```

| Параметр | Обяз. | Значение в проекте | Смысл |
|---|---|---|---|
| `lat`, `lon` | да | из геокодинга или от пользователя | координаты точки |
| `appid` | да | ключ из `.env` | авторизация |
| `units` | нет | `metric` | °C, м/с (по умолчанию — кельвины) |
| `lang` | нет | `ru` | язык описания погоды |

Поля ответа, которые использует проект:

| Поле | Смысл |
|---|---|
| `main.temp` | температура в °C (при `units=metric`) |
| `main.feels_like` | «ощущается как», °C |
| `main.humidity` | влажность, % |
| `weather[0].description` | описание, например «пасмурно» |
| `weather[0].main` | короткая группа: `Clouds`, `Rain`, … |
| `wind.speed` | ветер, м/с |
| `name` | название населённого пункта, найденного по координатам |
| `dt` | время расчёта, unix-время UTC |
| `cod` | код ответа внутри JSON (`200` при успехе) |

Без `units=metric` температура приходит в кельвинах: 281 — это не «-8 °C»,
а 7.85 °C после перевода.

## 3. HTTP-статусы

| Статус | Что значит | Реакция проекта |
|---|---|---|
| `200` | успех | разбираем JSON |
| `400` | некорректный запрос (пустой `q`) | сообщение пользователю |
| `401` | неверный или неактивный ключ | подсказка про `API_KEY` в `.env` |
| `404` | ничего не найдено | сообщение «проверьте город/координаты» |
| `429` | превышен лимит запросов | 3 повтора с паузами 1, 2, 4 с, затем предложение кэша |
| `5xx` | сбой на стороне OpenWeather | 3 повтора, затем предложение кэша |

Бесплатный тариф OpenWeather — порядка 60 запросов в минуту на аккаунт
(лимиты меняются, актуальные значения — в личном кабинете).

## 4. Особенности ключа

- Ключ создаётся в разделе **My API keys** и **не скрывается** в интерфейсе.
- Новый ключ может активироваться не мгновенно: от нескольких минут до пары часов.
  Ответ при этом — `401 Invalid API key`.
- Ключ передаётся как параметр `appid` в URL. Секрет в коде не хранить: только `.env`.

## 5. Ошибка внутри JSON

Иногда API отвечает со статусом не 200 и телом вида:

```json
{"cod": 401, "message": "Invalid API key. Please see ..."}
```

Поэтому проект дополнительно показывает `message`, если сервер его прислал.
