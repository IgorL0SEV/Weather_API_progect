# Конспект VPd03 — авторизация и ключи

## 1. Зачем нужен API-ключ

Ключ — это пропуск. Сервис по нему понимает, **кто** делает запрос, и решает:

- пускать или нет (иначе — `401 Unauthorized`);
- сколько запросов разрешить (лимиты и тарифы);
- какую статистику записать на аккаунт.

Ключи бывают у OpenWeather (`appid`), Telegram Bot API (токен бота), Google Maps,
у AI-провайдеров. Общий сценарий: регистрация → личный кабинет → генерация ключа →
сохранение на своей машине.

## 2. Чем опасен ключ в коде

Ключ, вписанный в `.py`, попадает в:

- историю git (даже если удалить строку позже — она остаётся в старых коммитах);
- публичный GitHub, где боты сканируют новые коммиты на токены;
- скриншоты, пересланные файлы, архивы.

Последствия: чужие запросы за ваш счёт, исчерпанные лимиты, блокировка аккаунта.
Крупные сервисы сами отзывают утёкшие токены и пишут владельцу, но OpenWeather,
например, этого не делает — отвечать за ключ приходится самому.

## 3. Как правильно: `.env` и переменные окружения

`.env` — текстовый файл в корне проекта, по строке на переменную:

```text
API_KEY=ваш_ключ
```

Код читает его через `python-dotenv`:

```python
from dotenv import load_dotenv
load_dotenv()
API_KEY = os.getenv("API_KEY")
```

`load_dotenv()` подгружает пары из файла в окружение процесса, а `os.getenv`
достаёт значение. В самом коде ключа нет — код можно публиковать.

Два обязательных условия:

1. **`.env` в `.gitignore`** — иначе смысл теряется.
2. **`.env.example` в репозитории** — шаблон с плейсхолдером, чтобы новый человек
   знал, какие переменные нужны.

В проекте путь к `.env` задан явно — рядом с `weather_app.py`. Так программа
работает при запуске из любой папки, а не только из корня проекта.

## 4. Два шага OpenWeather: геокодинг и погода

Погоду API отдаёт по координатам, а пользователь знает название города. Поэтому:

1. **Geocoding API** `geo/1.0/direct` — название → `lat`, `lon`;
2. **Current Weather API** `data/2.5/weather` — координаты → JSON с погодой.

Важные детали:

- геокодинг возвращает **массив**; нужен первый элемент (`[0]`) — самый популярный город;
- `limit=1` ограничивает выдачу одним совпадением;
- город не найден — это `200` и пустой список, а не `404`;
- `units=metric` переводит температуру в °C и ветер в м/с;
- `lang=ru` даёт описание погоды по-русски.

## 5. Ошибки, которые нельзя превращать в трейсбек

Пользователю нужен понятный текст, а не `Traceback`. В проекте различаются:

| Ситуация | Что видит пользователь |
|---|---|
| нет ключа | как создать `.env` и где взять ключ |
| `401` | ключ не принят; новый может активироваться не сразу |
| пустой геокодинг | «Город не найден, проверьте написание» |
| `429` / `5xx` / сеть | повторы 1, 2, 4 с, затем предложение кэша |
| битый JSON | «OpenWeather вернул не JSON» |

Для этого введены два своих исключения: `WeatherError` (ошибка пользователя)
и `WeatherUnavailableError` (временная недоступность — можно показать кэш).

## 6. Повторы и троттлинг

`429 Too Many Requests` означает «слишком часто». Вместо немедленного падения
делаем до трёх повторов с паузой 1, 2, 4 секунды — экспоненциальный рост.
Повторяем только временные сбои: `429`, `5xx`, таймаут, обрыв соединения.
`401`, `404` и `400` повторять бессмысленно — от повтора ответ не изменится.

## 7. Кэш последнего ответа

Кэш — это файл `weather_cache.json` с последним успешно полученным ответом
и метаданными:

```json
{
  "city": "Москва",
  "lat": 55.752,
  "lon": 37.6156,
  "fetched_at": "2026-11-15T17:30:00+00:00",
  "weather": { "...": "ответ Current Weather API" }
}
```

Зачем: если сеть пропала, пользователь не остаётся с пустым экраном. Но данные
о погоде быстро стареют, поэтому предлагаем кэш, только если ему меньше трёх
часов. Возраст считается по `fetched_at`, а не по времени файла: файл можно
переписать, метаданные — честнее.

## 8. Разделение слоёв

`weather_app.py` содержит и сетевой слой, и интерфейс, но логически они разделены:

- **функции API** возвращают данные (`tuple`, `dict`) и не печатают;
- **CLI** решает, что показать и как оформить;
- **кэш** — отдельные `save_cache` / `load_cache` / `cache_age_hours`.

Поэтому функции можно тестировать без сети, а меню менять, не трогая запросы.
